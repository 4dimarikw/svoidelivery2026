# S07: время и обмен Telegram initData

Проверка полей выполняется до числовых преобразований и HMAC. Массивы,
нецелые/отрицательные ID, некорректные JSON-поля пользователя и неоднозначные
query-поля initData отклоняются. Для Widget и Mini App используется
`hash_equals`; vendor-код не изменён.

TTL сохранён: Widget — 60 секунд, Mini App — 86400 секунд. Допустимое смещение
в будущее — 30 секунд (`telegram-auth.future_skew_seconds`). Границы включены.
Проверка алгоритма: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app

Первый обмен проверенной подписи Mini App привязывается к случайной серверной
метке сессии. Повтор в этой сессии разрешён, в том числе после регенерации её ID.
Та же подпись в другой сессии отклоняется до конца TTL. Новая подпись при новом
запуске разрешена. В хранилище сохраняются только отпечаток подписи и случайная
метка — исходного initData там нет. Существующая авторизованная сессия продолжает
работать по обычным правилам Laravel, независимо от TTL initData.

Если cookie/серверная сессия потеряны, старый initData не откроет новую сессию:
пользователь получает предложение закрыть и снова открыть Mini App.
Автоматические тесты проверяют этот контракт; реальный UX на клиентах Telegram
не проверялся. Приёмка на тестовом боте: открыть приложение, войти, перейти
между страницами, повторить вход, затем закрыть и открыть заново.

Учёт обменов использует `Cache::add` (атомарное добавление) в хранилище
`telegram-auth.webapp_exchange_cache_store`, по умолчанию — текущий cache store.
На одном сервере допустим file; на нескольких нужен общий Redis/database.
Array/null и непостоянные кеши непригодны для production. Очистка/вытеснение
кеша снимает учёт уже использованных подписей; это ограничение кеша, не HMAC.
При ошибке хранилища новый обмен отклоняется. Первый обмен украденной подписи
до легитимного пользователя этой мерой не предотвращается.

# S08: журналирование

`SafeLoggingServiceProvider` подключает общий `LogRedactor` к Laravel LogManager.
Обрабатываются message/context, исключения, extra Monolog и MessageLogged;
объекты исключений заменяются безопасными Throwable без аргументов стека.
Маскирование применяется к настроенным каналам, динамическим файловым каналам
и emergency fallback. События в `event_logs` используют тот же обработчик.

Удаляются значения ключей паролей, токенов, authorization/cookie/initData,
подписей; credentials в URL, query HTTP URL, токен webhook-маршрута (включая
настроенный шаблон), Telegram Bot API URL и типовые токены в тексте. Это
защита известных структур и форматов, а не распознавание любого произвольного
короткого секрета без имени поля. Не передавайте исходные запросы и секреты
в диагностические сообщения даже при включённом маскировании.

Каждая запись получает созданный сервером `correlation_id`. Он одинаков для
событий и логов в текущем запросе; перед следующей задачей очереди сбрасывается.
Класс исключения, место возникновения и стек без аргументов сохраняются.
Маршруты Telegram исключены из Debugbar; в production Debugbar выключен.
initData и подписи исключены из flash-полей обработчика ошибок валидации.

В текущем драйвере `database-uuids` новые payload `failed_jobs` шифруются
Laravel Crypt, текст исключения маскируется. `queue:retry` расшифровывает
payload и сохраняет штатное поведение задачи. Список ошибок не расшифровывает
payload. Старые записи читаются совместимо, но не переписываются автоматически.
Другие драйверы failed jobs этим адаптером не шифруются.

Сроки: event_logs — 90 дней, failed_jobs — 7 дней; переменные
`EVENT_LOG_RETENTION_DAYS` и `FAILED_JOB_RETENTION_DAYS`. Ежедневная команда
`logs:prune-sensitive` подключена к существующему Laravel scheduler.
Доступ к event_logs остаётся под явными разрешениями MoonShine; обычная роль
без прав читать журнал не может. Для новых single/daily/security-файлов
заданы права 0600 (на POSIX; на Windows используются ACL).

## Развёртывание и внешние ограничения

- Обновить конфигурационный кеш и перезапустить workers вместе с новым кодом.
  Для ротации основного файла установить `LOG_STACK=daily` в действующем .env;
  `.env.example` уже обновлён. Стандартный daily хранится 14 дней.
- Проверить работу существующего scheduler. Очистка журналов вне тестовой БД
  при реализации не запускалась.
- Сохранять ключ шифрования для чтения отложенных ошибок. Не откатывать
  обработчик failed_jobs без предварительного решения для зашифрованных записей.
- Маскирование не переписывает исторические логи, старые failed_jobs или бэкапы.
- PHP startup/error logs вне Laravel, reverse-proxy/access logs и резервные
  копии хостинга не проходят через этот процессор. В панели хостинга или через
  поддержку запросить исключение query/секретного сегмента webhook из логов,
  доступ к логам и бэкапам только администраторам, шифрование резервных копий
  с отдельным хранением ключей и срок хранения не более 30 дней. После восстановления
  старой копии применить действующие сроки очистки повторно.

Изменений настройки reverse proxy, прав хостинга или его резервных копий
из приложения не выполнялось. Эта внешняя часть S08 остаётся операционной задачей.
