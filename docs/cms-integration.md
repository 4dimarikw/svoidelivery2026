# Laravel Content CMS в проекте

Проект использует `dimarik/laravel-content-cms` 2.0.1. Модели, реестр типов,
структурные observers, URL-проверки и действия меню принадлежат пакету.
Собственные формы MoonShine, policies, типы и публичная вёрстка остаются в приложении.

## Код приложения

- `config/content-cms.php` регистрирует `about_info` и `footer_info`.
- `config/content.php` содержит только карту публичных компонентов и каталог иконок.
- Прикладной `Domain\Content\Types\AbstractContentBlockType` расширяет пакетную базу
  помощником выбора иконок. Новые типы и правила групп создаются в приложении.
- `LoadPublicPage` сохраняет результат `sections`, `menu`, `settings`, используя
  `LoadPublishedSections`. `LoadSiteMenu` вызывает `BuildMenu('main')`,
  `LoadSiteFooter` — `LoadPublishedSectionByKey('footer')`.
- Загрузчики меню и подвала имеют scoped lifetime: результат используется повторно
  внутри запроса, но не сохраняется между запросами долгоживущего worker.
- Разделы без маршрута имеют `route_name = null`, пустой якорь и не являются целями меню.
  В публичном диспетчере непустой якорь выводится один раз вокруг блоков раздела.

## Админка и права

Пять ресурсов остаются в `App\MoonShine\Resources` и обнаруживаются существующим
MoonShine provider. Генерировать второй комплект или подключать provider каркаса не нужно.
`ContentCmsIntegrationServiceProvider` связывает пакетные модели с прикладными policies.
Manager сохраняет доступ на редактирование контента; создание, удаление и изменение
служебных полей запрещены. Подмена скрытых полей проверяется сервером.

Блок и элемент создаются в два этапа: сначала основные поля, затем содержимое.
Формы используют правила типа/группы при редактировании, сохраняют пустые JSON-списки
и поддерживают именованные коллекции изображений и файлов.
Импорт/экспорт приложения оставлен в прежнем объёме; пакет не предоставляет обмен контентом.

## Данные и media

Миграции приложения объединены для чистой установки через `php artisan migrate:fresh --seed`.
Основная миграция CMS сразу создаёт обязательный ключ пункта меню длиной 100
и уникальный индекс `site_menu_items_menu_key_unique` по `site_menu_id` и `key`.
Начальная миграция пакета не публикуется.

Отдельные переносы списков «О нас» в JSON и имён моделей прав удалены:
сидеры уже содержат JSON-списки и используют `ContentCms\Models`.
`DatabaseSeeder` восстанавливает контент через `CurrentSiteDataSeeder`;
снимок включает актуальный JSON и сохранённые исторические элементы.
Отдельный `SiteContentSeeder` также содержит актуальный JSON.
Таблица `category_match_rules` больше не создаётся: правила находятся в
`config/category_matching.php`, обе миграции временной таблицы удалены.

Этот набор миграций рассчитан на пересоздание базы, а не обновление старой установки.
Команда `migrate:fresh --seed` удаляет существующие таблицы и заполняет базу заново.

Morph map сохраняет старые discriminator-значения `Domain\Content\Models\ContentBlock`
и `Domain\Content\Models\ContentBlockItem`. Эти значения разрешаются в пакетные модели
и используются при новых загрузках. Это строки совместимости, а не оставленные классы.
Глобальный `enforceMorphMap` не используется.

## Проверки и откат

Тесты используют отдельную MySQL-БД и временный media-диск. `PackageIntegrationTest`
проверяет двухэтапные формы, общие разделы, локальные ссылки, media, отсутствие SQL
при выводе компонентов и целостность дерева. `PackageMigrationTest` проверяет
окончательные ограничения ключей меню и сидирование прав пакетных моделей.
`OrderItemSnapshotMigrationTest` проверяет чистую установку с сидерами,
отсутствие таблицы правил категорий, полный откат и повторное применение миграций.

Перед локальным переходом создана резервная копия в игнорируемом Git каталоге
`data/cms-adoption-20260912`: `database-before.sql`, `baseline.json`, `before/`,
`media-before/`. Восстановление проверено в отдельной БД; содержимое этих файлов
не следует добавлять в Git. Каталог `verification/` содержит изолированную копию приложения.

После объединения миграций отдельный откат преобразований старых данных недоступен.
Для возврата к версии до интеграции требуется согласованное восстановление совместимых
кода, БД и media из резервной копии с учётом последующих записей.
Откат основной миграции CMS удаляет её таблицы.
