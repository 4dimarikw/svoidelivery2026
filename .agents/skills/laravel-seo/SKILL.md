# Laravel SEO

Помогай внедрять установленную версию `dimarik/laravel-seo`, сохраняя архитектуру и настройки приложения.

Сначала изучи `composer.json`, `bootstrap/app.php`, `bootstrap/providers.php`, `config/seo.php` (если опубликован), `.env.example`, основной layout и способ его подключения (`@extends` или компонент), существующие `<title>`/`<meta>` в шаблонах, маршруты и файлы `robots.txt`, миграции с таблицей `seo`, модели со slug и места, где slug меняется. Если пакет уже установлен, считай README и исходники в `vendor/dimarik/laravel-seo` источником истины для конкретной версии. Не редактируй `vendor`; меняй файлы приложения или версию зависимости.

Уточняй только решения, которые нельзя вывести из проекта: должен ли сайт индексироваться в каждом окружении, какие маршруты закрыть от индексации, нужен ли `robots.txt` от пакета, нужны ли ресурсы MoonShine и кому они доступны, какие модели меняют публичные адреса. Не включай индексацию production-сайта, не удаляй существующие `robots.txt` и SEO-данные и не переноси записи в реальной БД без запроса пользователя.

Соблюдай инварианты пакета:

- в таблице `seo` хранятся только локальные адреса вида `/path?query`; присваивание `url` нормализует значение через `SeoUrl::forStorage()`, для форм применяй `SeoPathRule`;
- запись для адреса со строкой запроса имеет приоритет над записью для пути; поля берутся по цепочке запись → `SeoPage` → `SeoDefaults` → `app.name`; `canonical` всегда задаёт приложение;
- компонент `<x-laravel-seo::meta>` не выполняет запросов к БД и экранирует вывод; не дублируй рядом собственные `<title>`, description и canonical;
- `seo.indexable` по умолчанию `false`: middleware ставит `X-Robots-Tag: noindex, nofollow` на все ответы, включая ошибки, только если ответы исключений тоже проходят через `PreventSiteIndexing::apply()`;
- маршрут `/robots.txt` пакета не перекрывает существующий маршрут или `public/robots.txt`; `sitemap_url` задаётся строкой, не `route()`;
- MoonShine не зависимость пакета: ресурсы генерируются командой `seo:moonshine-stubs`, принадлежат приложению и требуют политики для `Dimarik\LaravelSeo\Models\Seo`;
- `SeoUrlMover::prepare()` и `apply()` вызываются в одной транзакции приложения вместе с изменением адреса; пакет не открывает и не повторяет транзакции;
- `SeoUrlsMoved` публикуется после commit, `SeoUrlMoveRejected` – при конфликте даже при откате; журналирование подключает приложение отдельным адаптером.

Для установки, настройки и индексации прочитай [references/installation.md](references/installation.md). Для вывода метаданных, view composer и MoonShine прочитай [references/usage.md](references/usage.md). Для переноса записей при смене адресов, событий и журналирования прочитай [references/url-moves.md](references/url-moves.md). Для проверки, что поля товаров и других сущностей не превышают лимиты SEO-заголовка и URL, прочитай [references/limits-audit.md](references/limits-audit.md). Загружай только относящиеся к задаче справочники.

После изменений запускай подходящие тесты приложения, `php artisan config:cache` и `php artisan route:cache` (затем очисти кэш, если в проекте он не используется в разработке) и проверки из раздела «Проверка» в `references/installation.md`. Реальную MySQL, production-заголовки и данные проверяй только когда среда и запрос пользователя это позволяют.
