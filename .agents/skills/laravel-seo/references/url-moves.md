# Перенос записей при смене адресов

## Где подключать

Найди места, где меняется публичный адрес страницы: смена slug, перенос в другой раздел, переименование маршрута с сохранением данных. Подключай `SeoUrlMover` в том же сервисе, action или контроллере, который сохраняет новый адрес, а не в observer: перенос должен идти в одной транзакции с изменением модели, и конфликт должен вернуться в форму.

```php
use Dimarik\LaravelSeo\SeoUrlMover;
use Illuminate\Support\Facades\DB;

DB::transaction(function () use ($product, $oldSlug, $mover) {
    $moves = $mover->prepare(["/product/{$oldSlug}" => "/product/{$product->slug}"]);
    $product->save();
    $mover->apply($moves);
}, attempts: 3);
```

- Ключи и значения карты – пути без строки запроса. Пустая карта и совпадающие пути ничего не делают.
- Вместе с путём переносятся его варианты со строкой запроса (`/product/a?campaign=vk`), но не `/product/ab` и не `/product/a/details`. Если вложенные адреса тоже меняются, добавь их в карту явно.
- Обмен адресами, циклы и цепочки допустимы в одном вызове. Целевой адрес свободен, если его владелец переносится в том же вызове.
- `prepare()` и непустой `apply()` без транзакции выдают `LogicException`. `attempts` в `DB::transaction` повторяет всю операцию при deadlock; сам пакет транзакции не открывает.
- `prepare()` возвращает элементы `record` (полная неизменённая модель) и `url` (окончательный адрес): используй их для предварительного просмотра и резервной копии перед `apply()`.

## Конфликты

`ValidationException` с ключом `url` означает, что адрес занят записью, которая не переносится, две записи получают один адрес или уникальный индекс отклонил адрес из-за параллельного запроса. Транзакция должна откатиться целиком. Переименуй ключ ошибки под поле формы приложения (например, `slug`), сохранив сообщение:

```php
try {
    DB::transaction(/* ... */);
} catch (ValidationException $exception) {
    throw ValidationException::withMessages(['slug' => $exception->errors()['url']]);
}
```

Некорректный целевой адрес (длина, формат) тоже даёт ошибку `url` до любой записи. Ошибки подключения, deadlock и таймауты блокировок пробрасываются как есть и конфликтом не считаются.

## Блокировки

Пакет читает и блокирует только переносимые записи и записи на целевых адресах через уникальный индекс `url` (на MySQL с `FORCE INDEX seo_url_unique`). Не меняй имя индекса и схему таблицы. Остальные записи SEO остаются доступны; запись на целевой адрес или смена `url` соседней в индексе записи может ждать commit переноса. Держи транзакцию короткой: не выполняй внутри неё HTTP-запросы, отправку почты и тяжёлые вычисления.

## События

- `Dimarik\LaravelSeo\Events\SeoUrlsMoved` (`operationId`, `count`, `changes` с `id`, `from`, `to`) – один раз после commit внешней транзакции; не публикуется при откате, предварительном просмотре и отсутствии изменений.
- `Dimarik\LaravelSeo\Events\SeoUrlMoveRejected` (`attemptId`, `reason`: `target_occupied`, `duplicate_target`, `unique_violation`; `urls`) – при конфликте, даже если транзакция затем откатывается.

События содержат только значения, без моделей и временных адресов `/__seo-move/...`. Исключения обработчиков пакет передаёт в `report()` и не меняет результат переноса. Обработчики, которые пишут в ту же БД, делай идемпотентными; очистку кэша страниц и редиректы со старого адреса вешай на `SeoUrlsMoved`.

## Журналирование

Если в приложении установлен `dimarik/laravel-event-logging`, подключай журнал по `vendor/dimarik/laravel-seo/docs/event-logging-adapter.md`: события журнала `seo.urls_moved` (`info`) и `seo.url_move_rejected` (`warning`) в production PSR-4 каталоге, listeners вне `app/Listeners` с явной регистрацией, запись только через `EventLogger::record()` без дополнительного `event()`, без строк запроса и SEO-текстов, не более 20 примеров. Учитывай требования проверенной версии logging-пакета (PHP 8.4, Laravel 12, MoonShine 4). Не включай Telegram без запроса пользователя.

## Тесты приложения

Покрой feature-тестами: перенос вместе с вариантами строки запроса, откат при ошибке сохранения модели, конфликт с ошибкой на поле формы, отсутствие `SeoUrlsMoved` после отката (`Event::fake([SeoUrlsMoved::class])`). Для проверки события после commit в тесте с `RefreshDatabase` оборачивай операцию в `DB::transaction()`: Laravel выполняет after-commit callbacks при фиксации этой транзакции.
